# Architecture - Run Once Duration Override Operator

## Overview

The Run Once Duration Override Operator manages a mutating admission webhook server that automatically sets `activeDeadlineSeconds` on run-once pods in OpenShift clusters. It reconciles a singleton `RunOnceDurationOverride` custom resource and deploys/configures the webhook server to prevent run-once pods (Jobs, CronJobs) from running indefinitely.

The operator runs in the `openshift-run-once-duration-override-operator` namespace and manages a single operand: the webhook server DaemonSet.

## Operator Startup Flow

```
cmd/run-once-duration-override-operator/main.go
  → RunOperator()                     [pkg/operator/start.go]
    → Reads RELATED_IMAGE_OPERAND_IMAGE env var
    → Creates operator informers and Kubernetes informers
    → NewTargetConfigController()     [pkg/operator/targetconfigcontroller/controller.go]
      → Builds handler chain (9 handlers)
      → Watches CR, Deployments, DaemonSets, Pods, ConfigMaps, Services, Secrets, ServiceAccounts, MutatingWebhookConfigurations
    → Starts informers and controller
```

## Operand

### Webhook Server DaemonSet

The webhook server runs on all master nodes and intercepts pod creation requests.

| Aspect | Detail |
|---|---|
| Deployment Type | DaemonSet (one pod per master node for HA) |
| Node Selector | `node-role.kubernetes.io/master: ""` |
| Host Network | `true` (binds to 127.0.0.1:9448) |
| Image | Specified via `RELATED_IMAGE_OPERAND_IMAGE` env var |
| Security | Non-root, read-only FS, all capabilities dropped, seccomp RuntimeDefault |
| TLS | Self-signed certificates generated by operator |
| Upstream Repo | [openshift/run-once-duration-override](https://github.com/openshift/run-once-duration-override) |

### Managed Resources

| Resource | Name | Purpose |
|---|---|---|
| ConfigMap | `runoncedurationoverride-configuration` | Webhook config (activeDeadlineSeconds value) |
| Secret | `server-serving-cert-runoncedurationoverride` | TLS serving certificate and key |
| ConfigMap | `runoncedurationoverride-service-serving` | CA certificate bundle |
| Service | `runoncedurationoverride` | Webhook endpoint |
| MutatingWebhookConfiguration | `runoncedurationoverrides.admission...` | Pod admission webhook registration |
| ServiceAccount | `runoncedurationoverride` | Webhook server identity |
| ClusterRole/RoleBindings | Various | RBAC for operator and webhook server |

## External Dependencies

The operator deploys a **separate webhook server binary** from [openshift/run-once-duration-override](https://github.com/openshift/run-once-duration-override). The operator does not contain any admission logic itself — it only manages the lifecycle (DaemonSet, certificates, configuration) of the webhook server. Both `RELATED_IMAGE_OPERAND_IMAGE` (webhook server image) and `OPERAND_VERSION` (reported operand version) environment variables are required in `deploy/07_deployment.yaml` and read by `RunOperator()` in `pkg/operator/start.go` — startup fails if either is missing.

## Handler Chain

The operator uses a handler chain pattern for reconciliation. Each handler receives the CR, performs its work, and passes the modified CR to the next handler.

| # | Handler | File | Purpose |
|---|---|---|---|
| 1 | AvailabilityHandler | `handler_availability.go` | Initial deployment availability check |
| 2 | ValidationHandler | `handler_validation.go` | Validates `activeDeadlineSeconds >= 0` |
| 3 | ConfigurationHandler | `handler_configuration.go` | Creates/updates webhook ConfigMap |
| 4 | CertGenerationHandler | `handler_cert_generation.go` | Generates TLS serving certs and CA |
| 5 | CertReadyHandler | `handler_cert_ready.go` | Verifies certs are populated and valid |
| 6 | DaemonSetHandler | `handler_deploy.go` | Creates/updates webhook DaemonSet |
| 7 | DeploymentReadyHandler | `handler_deployment_ready.go` | Checks DaemonSet pods are ready |
| 8 | WebhookConfigurationHandler | `handler_webhook.go` | Creates/updates MutatingWebhookConfiguration |
| 9 | AvailabilityHandler | `handler_availability.go` | Final availability check and status update |

All handlers are in `pkg/operator/targetconfigcontroller/`.

## Webhook Request Flow

```
1. User creates/updates Pod (restartPolicy: Never or OnFailure) in labeled namespace
2. API Server checks MutatingWebhookConfiguration (matches CREATE and UPDATE)
3. API Server calls webhook: POST https://localhost:9448/...
4. Webhook server checks restartPolicy and activeDeadlineSeconds
5. If conditions met, patches pod.spec.activeDeadlineSeconds
6. Pod is created with enforced deadline
```

**Namespace opt-in label**: `runoncedurationoverrides.admission.runoncedurationoverride.openshift.io/enabled: "true"`

## Status Reporting

The operator reports status via the `RunOnceDurationOverride/cluster` CR:

| Field | Purpose |
|---|---|
| `status.conditions` | Standard operator conditions (Available, Progressing, Degraded) plus handler-specific conditions |
| `status.resources.*Ref` | Object references to managed resources (ConfigMap, Secret, DaemonSet, etc.) |
| `status.hash.configuration` | Hash of ConfigMap content (triggers pod restart on change) |
| `status.hash.servingCert` | Hash of serving cert (triggers pod restart on rotation) |
| `status.hash.observedConfig` | Hash of observed operator config |
| `status.image` | Current operand image |
| `status.certsRotateAt` | When certificates will be rotated |

### Condition Types

| Condition | Trigger |
|---|---|
| InstallReadinessFailure | General installation/readiness issues |
| InvalidParameters | `activeDeadlineSeconds < 0` |
| ConfigurationCheckFailed | ConfigMap creation/update failed |
| CertNotAvailable | Serving certificates missing or invalid |
| CannotSetReference | Failed to set object reference in status |
| CannotGenerateCert | Certificate generation failed |
| InternalError | Unexpected controller errors |
| AdmissionWebhookNotAvailable | MutatingWebhookConfiguration not ready |
| DeploymentNotReady | DaemonSet pods not running |
